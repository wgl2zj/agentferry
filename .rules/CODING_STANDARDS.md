# CODING_STANDARDS.md — 代码与测试规范细则

> 细则文件。由 AGENTS.md 任务路由表加载（代码修改/测试类任务）。
> 标记规则：【强制】违反即违纪；【应当】偏离需说明；【可选】无后果。
> 技术栈特定条款已按项目画像（Electron 主进程 TypeScript 后端 / React + TypeScript 前端桌面应用，Windows/macOS/Linux 三平台，无自有数据库）于 2026-08-17 生成注入，2026-09-06 随 Rust→TS 架构迁移改写。

## 注释与文档

- 【强制】每个源码文件首行必须有模块级说明（TS 文件头注释），一句话说明职责。
- 【应当】注释写"为什么做"，非直观逻辑必须注释。
- 【强制】修改逻辑时同步更新模块说明和行内注释。
- 【应当】导出函数与 IPC 命令逐步补充 TSDoc 注释，优先覆盖打包/覆盖/同步引擎的公共接口；仅补注释时不得顺手改变运行逻辑。

## 后端规范（Electron 主进程 / TypeScript）

- 【强制】IPC 命令集中注册于唯一的 `handle()` 装配（`electron/main.ts`）；新增命令必须先在 `electron/protocol.ts` 的 `COMMANDS` 登记并同步注册，不散落多处。
- 【强制】command 统一错误协议：引擎与命令层错误归一为 `AppError`（`electron/engine/error.ts`，`code` 稳定不变），经 `{ok,error}` 信封跨桥、预加载层还原为异常；命令边界禁止非受控断言（`!`/`as` 直传）。
- 【强制】长任务（打包、校验、执行）不阻塞主进程：异步流式实现（fs stream + await 分片让出事件循环），进度经 `progress` 事件按 50ms 节流汇报（首条与末条必发）。
- 【强制】不可逆写操作（覆盖 apply、删除文件、向目标目录同步写入）必须先产出 dry-run 变更计划（新增/覆盖/删除文件清单），经用户在 UI 确认后执行。
- 【强制】源资产目录（如 `~/.zcode/` 等 agent 资产目录）默认只读；写入目标必须来自用户显式选择的输出路径。
- 【强制】SQLite 源库不解析、不修改内容；检测到 `-wal`/`-shm` 文件存在时，警告"源程序未完全退出"并拒绝打包该库。
- 【强制】文本改写（如本机路径替换）保持原文件编码与 BOM 状态：UTF-8 无 BOM 文件改写后仍不得引入 BOM。
- 【强制】路径一律使用 `node:path` 的 `join`/`dirname` 构造，禁止手拼 `\` 或 `/` 分隔符字符串（三平台一等公民）。
- 【强制】打包时生成 SHA-256 清单；apply 后逐文件复验哈希，不匹配立即停止并报告差异文件。
- 【强制】错误显式处理：异步引擎的 Promise rejection 必须捕获或向上传播，不得静默吞掉；访问用户资产的链接（junction/符号链接）一律按物理路径访问，禁止穿越链接。

## 前端规范（React + TypeScript）

- 【强制】函数组件 + Hooks，不新增 class 组件（错误边界除外）。
- 【强制】前端调用后端统一走类型化 IPC 封装（`src/lib/ipc.ts` 的 `call()`，命令名常量唯一来源为 `electron/protocol.ts`；组件经 `apiCall()` 使用），不散写未类型化的命令字符串。
- 【强制】后端事件（进度、日志、阶段变化）统一走 `src/lib/ipc.ts` 的 `useBackendEvent` / `src/lib/mock.ts` 的 `useProgress` 封装，不散落各组件。
- 【强制】状态用 `useState`/`useReducer`/`useContext`（或项目后续选定的状态方案），不散落全局变量。
- 【强制】副作用用 `useEffect`，必须正确清理订阅/定时器，依赖数组显式。
- 【强制】列表渲染用稳定 `key`，顺序变化时不用数组 index 作 key。
- 【强制】表单受控/非受控统一一种风格，不混用。
- 【强制】设计令牌（颜色/间距/圆角）从 `src/styles/tokens.css` 取，不内联十六进制颜色值（详见 `.rules/UI_DESIGN.md`「设计令牌」）。

## 测试规范

- 【强制】任何情况下都不得自主运行全量回归（`npm test`），是否全量回归由用户决定。
- 【应当】日常小范围修改优先运行直接相关测试，并在汇报中说明跑了哪些、为什么跑这些。
- 【强制】新增或修改会随资产文件数增长而变慢的扫描、哈希、同步代码时，必须新增或更新规模回归测试：分别构造小文件集与大文件集，断言耗时或关键操作次数不随文件数线性恶化；不得只用单文件证明"功能可用"。
- 【强制】dry-run 安全铁律必须有反向测试：未经用户确认执行操作时，断言目标目录完全不变。
- 【强制】编码保持必须有回归测试：路径替换等文本改写后，断言字节级未引入 BOM、未改变原编码。
- 【应当】本次改动触及打包/覆盖/同步核心引擎、文件校验、Electron IPC 命令边界、跨模块共享接口、公共基础服务，或临近发版时，不要自行运行全量回归，而是在任务结束的汇报中提出"建议进行全量回归"并说明理由，由用户决定。
- 【强制】用户明确要求执行测试时，按用户要求执行（含全量回归）。
- 【强制】前端关键路径使用 E2E 标记测试，默认跳过、显式开启后才运行。
- 【强制】前端 E2E 必须使用临时测试目录（构造假的 agent 资产目录树），不得触碰真实家目录下的资产。
- 【应当】测试命名遵循项目约定：引擎测试沿用 Rust 时代 `模块_场景` 风格的测试名（保持与 FEATURE_MAP 锁定标注一致）；前端组件测试用 vitest 描述性语句。
- 【应当】断言统一使用框架标准断言（Rust：`assert!`/`assert_eq!`；前端：vitest `expect`）。

## 任务完成清单

### 普通代码修改/测试

- [ ] 修改范围与用户要求一致，没有夹带无关重构。
- [ ] 直接相关测试或等价定向验证已执行并通过；未执行项已说明理由。
- [ ] 新增或修改逻辑所需的注释、模块说明和类型信息已同步。
- [ ] 涉及可增长文件集的扫描/哈希/同步路径，已有小/大规模回归测试证明不随文件数线性恶化。
- [ ] 临时日志、探针、调试文件和一次性兼容代码已清理。
- [ ] 已检查 `git diff`（代码差异），确认提交只包含本轮相关文件。
- [ ] 已向用户汇报改动、提交、推送、测试和手动验证需求。

### Bug 修复附加项

- [ ] 已记录可观察的原始现象和根因证据，不以猜测替代复现。
- [ ] 有正确测试接缝时，回归测试能在修复前失败、修复后通过；无正确接缝时已明确说明。
- [ ] 原始复现场景已重新验证，且没有遗留调试插桩。
