# Ticket 06：前端界面（浅色系现代 UI，端到端视觉验收）

Status: done
Type: task

## 目标

实现全部页面与交互：首页（两功能卡+最近任务）、打包向导 4 步、解包向导 5 步（含 dry-run 四组确认与冲突改判、路径适配清单）、设置页。浅色系、设计令牌制、消息四通道、无原生弹窗、键盘可达。**本票由 KIMI-K3 子智能体端到端实现并截图验收（视觉任务路由规则）**，主模型提供 IPC 契约（Ticket 05）与 tokens.css 基底。

## 页面与状态

1. 首页：`资产摆渡` 品牌、打包/解包两大卡、最近任务列表（空状态说明+下一步）
2. 打包向导：①选档案（v1 仅 ZCode，展示档案只读说明）②盘点结果（类别树+体量+可迁移性图标；WAL 阻断走横幅+"重新检测/跳过该库"两动作）③档位（推荐/完整/自定义）+输出路径选择 ④执行（进度+阶段+失败项）→打包报告
3. 解包向导：①选包并校验（哈希逐文件进度）②内容预览（类别树）③模式选择（覆盖/增量说明卡）+路径适配清单（旧串→新串，可编辑，逐条确认）④dry-run 四组计划确认（冲突组逐条/整组改判；统一确认对话框显示对象/影响/后果）⑤执行+验证报告（成功/失败清单+备份位置）
4. 设置页：默认输出目录、备份保留策略展示（只读 v1）、档案管理（只读）

## 验收

- [ ] 每页恰好一个可见 h1；页面骨架符合 UI_DESIGN.md 三.1 顺序
- [ ] 全部颜色走 tokens.css 变量，无内联十六进制
- [ ] 1024×768 与 1440×1000 无横向滚动
- [ ] 长任务进度显示阶段/当前/总数；>1s 有加载态；空状态含"为什么+下一步"
- [ ] 确认对话框：显示对象、影响、操作后状态；WAL 阻断/打包完成走横幅；轻量反馈走 Toast
- [ ] 键盘焦点可见、弹窗焦点进出管理、图标 aria、状态不只靠颜色
- [ ] `npm run build` 通过；vitest 组件测试（向导步骤流转、四组计划渲染、冲突改判交互）通过
- [ ] 浏览器截图验收（KIMI-K3 自主完成）：浅色现代观感达标
